# `FileWriterTool`

## 설명

`FileWriterTool`은 파일에 텍스트를 씁니다. 없는 디렉터리는 자동으로 만들어집니다. 기본 인코딩은 UTF-8입니다. 이 도구는 텍스트만 쓰며, 바이너리 파일은 쓰지 않습니다.

쓰기는 `base_dir` 안에 머뭅니다. 기본값은 현재 작업 디렉터리입니다.

## 설치

```shell
pip install 'crewai[tools]'
```

## 예시

```python Code
from crewai_tools import FileWriterTool

file_writer_tool = FileWriterTool()

result = file_writer_tool.run(
    filename='example.txt',
    content='This is a test content.',
    directory='test_directory',
)
print(result)
```

## 인자

에이전트가 런타임에 제공하는 값:

- `filename`: `directory`를 기준으로 쓸 파일 이름입니다. 하위 디렉터리를 포함할 수 있으며, 없으면 생성됩니다.
- `content`: 쓸 텍스트입니다.
- `directory` (선택 사항): 쓸 디렉터리입니다. 상대 경로는 도구의 허용 디렉터리(`base_dir`이 설정된 경우 그 값, 그렇지 않으면 현재 작업 디렉터리) 안에서 해석되며, 기본값은 해당 디렉터리의 루트(`./`)입니다. 없으면 생성됩니다.
- `overwrite` (선택 사항): 기존 파일을 덮어쓸지 여부입니다. `true`/`false`를 받습니다(`yes`/`no`, `on`/`off`, `1`/`0`도 가능). 기본값은 `false`이며, 이 경우 파일을 바꾸지 않고 오류를 반환합니다.

도구를 생성할 때 설정하는 값:

- `base_dir` (선택 사항): 쓰기가 머물 수 있는 디렉터리입니다. 기본값은 쓰는 시점의 현재 작업 디렉터리입니다. 설정한 경로는 도구가 생성될 때 해석되므로, 이후 작업 디렉터리를 바꿔도 이동하지 않습니다.
- `encoding` (선택 사항): 파일을 쓸 때 사용하는 텍스트 인코딩입니다. 기본값은 `utf-8`입니다.

## 허용 경로

런타임의 `directory`와 `filename`은 보통 LLM이 선택합니다. 쓰기는 샌드박스로 제한됩니다:

- 해석된 `directory`는 `base_dir` 안에 있어야 합니다(`base_dir`을 설정하지 않으면 쓰는 시점의 현재 작업 디렉터리).
- 해석된 파일 경로는 그 `directory` 안에 있어야 합니다.
- 두 검사 전에 `..` 세그먼트, 절대 경로, 심볼릭 링크가 해석되므로 이를 써서 벗어날 수 없습니다.

작업 디렉터리 밖에 쓰려면 대상 트리로 `base_dir`을 지정하세요:

```python Code
file_writer_tool = FileWriterTool(base_dir='/var/output')
```

<Note>
이전에는 절대 `directory`가 프로세스 권한이 있는 임의의 위치에 쓸 수 있었습니다. 그 동작에 의존했다면 허용할 트리로 `base_dir`을 설정하세요. `CREWAI_TOOLS_ALLOW_UNSAFE_PATHS=true`를 설정하면 이전 동작이 복원되지만, URL을 가져오는 도구의 SSRF 보호를 포함해 모든 crewai-tools 도구의 경로 및 URL 검사가 프로세스 전역으로 꺼집니다. `base_dir`을 선호하세요. 관리형 워커에서는 `CREWAI_TOOLS_FORCE_SAFE_PATHS=true`를 설정해 테넌트가 해당 검사를 끄지 못하게 하세요.
</Note>
