# `FileWriterTool`

## Descrição

O `FileWriterTool` escreve texto em um arquivo. Diretórios ausentes são criados automaticamente. A codificação padrão é UTF-8. A ferramenta escreve só texto, não arquivos binários.

As escritas ficam dentro de `base_dir`, que por padrão é o diretório de trabalho atual.

## Instalação

```shell
pip install 'crewai[tools]'
```

## Exemplo

```python Code
from crewai_tools import FileWriterTool

file_writer_tool = FileWriterTool()

result = file_writer_tool.run(
    filename='example.txt',
    content='This is a test content.',
    directory='test_directory',
)
print(result)
```

## Argumentos

O agente fornece estes em tempo de execução:

- `filename`: Nome do arquivo a escrever, relativo a `directory`. Pode incluir subdiretórios, que são criados se não existirem.
- `content`: O texto a escrever.
- `directory` (opcional): Diretório no qual escrever. Um caminho relativo é resolvido dentro do diretório permitido da ferramenta (`base_dir` quando definido; caso contrário, o diretório de trabalho atual) e tem como padrão a raiz desse diretório (`./`). É criado se não existir.
- `overwrite` (opcional): Se um arquivo existente deve ser substituído. Aceita `true`/`false` (também `yes`/`no`, `on`/`off`, `1`/`0`). O padrão é `false`, que retorna um erro em vez de substituir o arquivo.

Você define estes ao construir a ferramenta:

- `base_dir` (opcional): Diretório dentro do qual as escritas devem permanecer. O padrão é o diretório de trabalho atual no momento da escrita. Um caminho que você define é resolvido na construção da ferramenta, então uma mudança posterior do diretório de trabalho não o move.
- `encoding` (opcional): Codificação de texto usada para escrever o arquivo. O padrão é `utf-8`.

## Caminhos permitidos

Como `directory` e `filename` costumam ser escolhidos por um LLM em tempo de execução, as escritas ficam confinadas a um sandbox:

- O `directory` resolvido deve estar dentro de `base_dir` (o diretório de trabalho atual no momento da escrita se você não definir `base_dir`).
- O caminho do arquivo resolvido deve estar dentro desse `directory`.
- Segmentos `..`, caminhos absolutos e symlinks são resolvidos antes das duas verificações, então não podem ser usados para escapar.

Para permitir que um agente escreva fora do diretório de trabalho, aponte `base_dir` para a árvore alvo:

```python Code
file_writer_tool = FileWriterTool(base_dir='/var/output')
```

<Note>
Anteriormente, um `directory` absoluto podia escrever em qualquer lugar em que o processo tivesse permissão. Se você dependia disso, defina `base_dir` para a árvore que deseja permitir. Definir `CREWAI_TOOLS_ALLOW_UNSAFE_PATHS=true` restaura o comportamento antigo, mas desativa verificações de caminho e URL em todo o processo para todas as ferramentas do crewai-tools, inclusive as proteções de SSRF nas ferramentas que buscam URLs. Prefira `base_dir`. Em workers gerenciados, defina `CREWAI_TOOLS_FORCE_SAFE_PATHS=true` para que um tenant não possa desativar essas verificações.
</Note>
